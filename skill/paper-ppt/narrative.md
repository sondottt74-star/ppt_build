# 内容与讲法规则

## 主线

- **主题一句话写在大纲开头**，每一页都要能回答“这页和主题什么关系”。主题是方法层面的概念（例：“结构化高斯”），不是泛泛的目标（例：“怎么把场景画好”）。
- **递进**：论文按“前一篇的局限 = 下一篇的动机”排序。每篇最后一页是局限，底部一条过渡条“→ 下一篇：让 X 再往前一步”。
- **贯穿例子**：选一个具体、可画的场景（同一栋建筑、同一段视频、同一个机器人任务），在开场主线页画成三联/多联图，每篇的“为什么”和总结页都回到它；总结页复用开场那张图，首尾呼应。
- **结构对照表**：开场一次（每篇一句话定位），总结一次（每篇：例子里的哪种情况 / 方法 / 结构 / 做了什么）。

## 开场（4–5 页）

1. 标题页：主标题 + 一句话副标题，列出论文，配一张最有代表性的论文原图。
2. 提纲：00 背景 + 每篇一行（编号方块用该篇主色）+ 总结。
3. 任务：输入什么、输出什么（两行流程：训练 / 推理），右下警示框写“不输出什么”。
4. 基础回顾：最基础的方法怎么表示、卡在哪里（2 张警示卡），公式 ≤ 3 个。
5. 主线：定义条（“A → B”）+ 贯穿例子三联图 + 每篇一张卡片，卡片间箭头。

## 每篇固定六步（面包屑就是这六步）

| 步 | 讲什么 | 常用版式 |
|---|---|---|
| 1 改了什么 | 相比前作/基线**改了哪几点**，先给结论，再说“哪些没变” | B 上图下卡 |
| 2 为什么 | 动机：直观原因 2 条 + 回到贯穿例子 | A 左图右文 |
| 3 方法 | 整体流程（论文 pipeline 原图 + 一行流程框）→ 关键模块各一页（公式 + 示意图 + 一个算例/表） | D、C |
| 4 训练 | 损失、增删/致密化、训练策略；只讲和本篇核心有关的 | A |
| 5 实验 | 主表（本文行高亮，名次色）+ 一张原生柱状图 + 3–4 张数字卡；消融/定性一页 | E、F |
| 6 局限 | 3–4 条，最后一条引出下一篇 | 2×2 警示卡 |

步骤名可按论文改（例：第三篇先讲“1 缺口”），但每篇都要有“改了什么”“实验”“局限”。

## 讲法

- **讲解简单，大纲不简单**：页面上一页一个意思、句子短、术语第一次出现时解释；细节写进大纲“讲什么”和逐字稿，不堆在页面上。被删掉的公式细节放备用页。
- 用大白话解释公式：每个符号一句“它是什么、变大意味着什么”，配一个小算例或表（例：d=8 → 用到 LOD 0–1）。
- 结论句放在页面底部条或右下结论框，页标题本身也写成结论（“实验：遮挡强的场景快 3–4 倍，质量不降”），不要写成“实验结果”。
- 中文为主，方法名、数据集名、指标保留英文；不要中英混杂成句。

## 讲稿（逐字稿）

- 页面给眼睛看，讲稿给耳朵听，两者分工：页面放结论和证据，讲稿放**串词**（这页为什么接在上一页后面）和**理解**（为什么这样设计、直觉、对比、代价、我的判断）。
- 串词要具体：用上一页的结论或遗留问题来接（“光照一变库就失效，那 SuperADD 怎么办？”），不用“接下来我们看”“这一页是”。
- 理解要落地：每个设计都回答一次“不这样会怎样”；每个关键数字回答一次“所以呢”。
- 对比贯穿全场：讲后一篇时主动和前一篇比（存储、时延、假设、失败案例），听众才能感到“递进”。
- 敢下判断：哪个提升主要来自更大的骨干、哪个数字口径不同不能直接比，讲稿里要说出来。
- 详细规则和正反例见 script-template.md。

## 数字与诚实

- 数字只从论文表格/正文抄（index.md 的 T#），写清数据集和设置；不同论文报告的同一方法数字不同，就分别注明来源，页面副标题提醒“不要混着比”。
- 有条件的结论要加“注意”警示卡（例：“3–4 倍只在遮挡强的场景；Berlin 只从 263 到 275”）。
- 本文方法不是全胜就如实标出（例：“Mip-NeRF360 上 SSIM/LPIPS 不如 3DGS”）。

## 结尾

- 总结页：对照表 + 竖向演进流程 + 一句话总结条。
- 讨论页：2 个开放问题，每个带一行提示方向。
- 备用页：大幅定性图、删掉的公式，不计入时长。

## 时长

每篇 6–7 分钟，开场 2 分钟，总结 1–2 分钟；三篇约 20–25 分钟、35–40 页。逐字稿按 250–280 字/分钟估算。
